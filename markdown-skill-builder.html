Agent-ready knowledge template

Markdown Skill Builder Template

Use Markdown to give knowledge a simple, reusable structure. Then use the Skill Builder to turn a trusted workflow into an instruction set that teams can test, maintain and use during transformation.

Why Markdown helps

Markdown is plain text with light formatting. It is easy to read, easy to update and gives people and AI systems useful cues about hierarchy, lists, steps, links and boundaries.

It does not make knowledge accurate by itself. Keep an owner, a review date and a link to the approved source.

Start with a real use caseUse Markdown for manager processes, policy summaries, employee journeys, knowledge articles, transformation playbooks and recurring operational guidance.

Structure

Headings

# Main title ## Section ### Subsection

Emphasis

**Important policy requirement** *Helpful context*

Lists

- Use bullets for checks or choices - Keep each point focused 1. Use numbers for steps in order 2. Keep the sequence clear

Useful references

Links

[Read the approved policy](https://example.com/policy)

Quote a requirement

> Policy requirement: submit the request at least four weeks in advance.

Code or exact wording

`Case status: pending approval`

Tables

Use tables when people need to compare a small set of structured options. Do not force long paragraphs into cells.

| Situation | First action | Owner | | --- | --- | --- | | Standard request | Follow the checklist | People Operations | | Exception | Escalate for review | Employee Relations |

Agent-ready notes

State the use case

**Use this when:** A manager receives a parental-leave request in Ireland.

State a boundary

## Boundaries - Do not give legal advice. - Escalate complex cases to the accountable team.

Show the source

**Owner:** People Operations **Last reviewed:** 12 November 2026 **Source of truth:** [Leave policy](internal-link)

Starter structure for a knowledge article

# [Topic] **Use this when:** [clear trigger] **Owner:** [team or role] **Last reviewed:** [date] **Source of truth:** [link] ## What this covers [short, factual scope] ## Steps 1. [action] 2. [action] 3. [action] ## Boundaries and escalation - Do not [restricted action]. - Escalate when [condition].

Syntax examples are adapted from the Markdown Cheatsheet by Markdown Here. Check the Markdown flavour used in your own tool, as support for tables and other features can differ.

Turn good practice into a reusable skill

A skill is a focused, repeatable set of instructions. It tells a person or agent when to use a workflow, which sources it can trust, what it must do, what it must not do and how to check the result.

Start narrowOne skill should support one defined type of work. Begin with a high-volume process or a reliable knowledge journey, then test and improve it before expanding its scope.

Skill settings

Copyable SKILL.md

This is a starting point. The accountable owner should review and approve the skill before it is used with live employee or business information.

    
Use it as part of transformation
  1. Start by improving one recurring knowledge journey.
  2. Use the Markdown structure to make the approved content easier to find and maintain.
  3. Create a focused skill for the repeatable work around it, including sources, guardrails and a human escalation point.
  4. Test with realistic questions, fix gaps and get owner approval before broader use.

    
Important: Do not put confidential employee, customer, health, payroll, legal or financial information into unapproved AI tools. Define the right data boundaries before testing any agent workflow.

  

  
Adapt this resource to your organisation’s policies, data controls and approval process before use.
